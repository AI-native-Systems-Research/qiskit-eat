What the change is

Prefer the shallower of two equal choices

Sabre constantly reaches ties — layout trials with the same swap count, candidate swaps with the same heuristic score — and broke them arbitrarily. This change breaks them by estimated two-qubit depth.

  • Layout-trial selection (layout.rs): key becomes (swap_count, est_2q_depth, index) instead of (swap_count, index).
  • Swap selection (route.rs): among swaps tied for the best score, keep those whose deeper qubit ends up shallowest; dag.rs records each node's 2q-gate count for the estimate.
  • Default-on, no new API. 3 Sabre source files, +159 / −6. It changes only ordering among equal options — never which options are considered.
Why gate count does not move. A tie is a set of options that already scored the same on swap cost. Picking the shallower one changes the depth of the result, not how many swaps are inserted, so two-qubit gate count is unaffected.

Correctness & acceptance

PASS — semantics preserved, guards clear

  • Verdict: PASS, score 1.094834 (D2 ratio 0.9134, trade √(D2·N2) 0.953).
  • C1–C5 exact small-circuit equivalence · C6 routing-replay reproduces exactly · C7 Clifford-variant equivalence — all pass on the evolved tree.
  • Every two-qubit gate in every output respects the target coupling map; routing is deterministic for a fixed seed.
  • N2 guard: overall −0.6% (passed); no per-case N2 above the 1.05× cap; cx / ecr basis panels both pass.
Bottom line. The change builds, preserves circuit semantics, and reduces two-qubit depth ~8.7% while leaving gate count flat — the smallest, safest of the EAT Sabre changes, and the natural first PR.
