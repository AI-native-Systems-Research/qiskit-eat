Proposed change

Break SABRE ties by two-qubit depth

Among options SABRE already scores as equal, prefer the one that adds the least two-qubit depth.

A tie-break only. It never changes which trials or SWAPs are considered, or any heuristic score — so the number of SWAPs, and the two-qubit gate count, stay the same. Only depth drops.

The gap

Today, ties break arbitrarily

SABRE's scoring often rates several options exactly equal. It then picks with no regard to the depth of the result.

  • Layout-trial selection. Several trials finish with the same swap count. SABRE keeps the one with the lowest trial index — min(swap_count, index). Index has nothing to do with circuit quality.
  • SWAP selection. During routing, several candidate SWAPs share the best heuristic score. SABRE picks one of them uniformly at random.
Both tie-breaks ignore the two-qubit depth the choice produces. Among options that are otherwise equal, one often routes the circuit's gates in fewer layers — that depth is left on the table by a coin flip.

The change

Resolve the tie by two-qubit depth

Track, per physical qubit, the running two-qubit depth reached so far.

a routed 2q node on (a, b):   depth[a] = depth[b] = max(depth[a], depth[b]) + (its 2q-gate count)

  • SWAP tie-break (route.rs): among the SWAPs tied for the best heuristic score, keep those whose deeper qubit ends up shallowest, then fall back to the existing random choice. The tracking is rolled back with SABRE's release valve. (dag.rs stores each node's 2q-gate count, num_2q.)
  • Layout-trial key (layout.rs): (swap_count, estimated 2q depth, index). The estimate replays the routed order once, counting a SWAP as three two-qubit gates.
It only re-orders options already judged equal on swap cost, so the number of SWAPs — and therefore the two-qubit gate count — cannot change. The routed gates are the same; they are packed into fewer layers.

One busy chain, two idle wires

5-qubit line. A prefix of gates keeps P0–P2 busy; P3 and P4 sit idle. Then a gate G = CX(q2, q4) must route.

G's qubits q2 and q4 are 2 edges apart, so one SWAP is needed. The blue prefix shares q1, so those gates stack up on P0–P2; P3 and P4 never get used.

Worked example · 3 of 3 · the decision

The tie-break keeps the shallower route

quantityA: SWAP(P2,P3)B: SWAP(P3,P4)
heuristic score (distance)−1−1  (tie)
SWAPs inserted11  (same)
deeper endpoint’s 2q depth40
finish depth of the block85

Same heuristic score, same one SWAP, same two-qubit gate count. But A stacks the SWAP on the already-deep P2 chain (4 + 3 + 1 = 8 layers), while B runs it on the idle wires and overlaps the busy prefix (max(4,3) + 1 = 5).

Without the tie-break: a 50/50 coin flip between A and B.  With it: always B — the shallower route. Same gates, fewer layers. Applied across every tie in layout search and routing, this is where the two-qubit-depth reduction comes from.
